## Fixed Reproducible Defects

### P1: Invalid offline measurements could retain a selector

In `src/gate_decision.py::pearson`, clamping a NaN quotient with Python's
`min`/`max` produced 1.0. A 40-pair pilot containing a NaN score could
therefore report perfect correlation, valid measurements, and retention.
Separately, four observed pairs were accepted even when the frozen pilot
required 40 from a declared pool of 400.

The fix rejects nonfinite inputs/intermediates before clamping, enforces
the required pilot count, and keeps invalid records JSON-serializable.
A genuinely smaller complete pool can still be measured in full. Whole-pool
overlap is not reported when only pilot pairs were supplied. Nonfinite or
boolean budgets/costs are rejected. Exact threshold equality no longer
serializes an infinite required sample size.

The numerical correlation calculation for normal finite inputs and the
registered threshold are unchanged. This establishes a possible failure
mode, not that any accepted historical row contained these invalid inputs.

### P2: Unknown or joint research costs were treated as selector costs

In `src/cost_accounting.py`, absent matrix stages and missing benchmark
timers could appear as zero cost. The automatic gate-rule suggestion also
assigned the full joint four-estimator stage to each individual reuse
estimator. Fresh stage timing includes reference/evaluation work.

Missing stage/benchmark times now remain unknown (`null`); negative and
nonfinite benchmark timers are also rejected as measurements. Complete
stage totals remain available as research-stage totals. Automatic marginal
selector-cost suggestions are intentionally empty until the required
allocation is measured. This does not make the existing stage accounting
an end-to-end cost ledger: update timers omit loading/saving, timestamp
differences can contain idle time, and recorded shard counts matter.

### P2: Node-ownership test omitted a current default arm

`tests/test_e5_node_ownership.py` prepared and checked three fake arms while
the production default includes difficulty (`passrate_beta`) as a fourth.
The fixture and its ownership assertions now cover all four. No launcher
or experiment recipe was changed for this repair.

## Open Scientific/Implementation Findings

### P1: The synthetic latent-ratio estimator is not the theorem's estimand

`src/gain_law_simulation.py:71` averages per-pool `noisy_gain/oracle_gain`.
The Gaussian proposition concerns `E[noisy_gain] / E[oracle_gain]`.
These are different statistics, even under its Gaussian assumptions.

A small-pool countercheck isolates the difference. For Gaussian scores,
`n=2`, `k=1`, and `rho=0.25`, the ratio of expected gains is 0.5; the
expected per-pool ratio is `(2/pi) * asin(sqrt(rho)) = 1/3`.
The existing implementation, with 50,000 repetitions and seed 20260913,
returned `0.329760`. A separate 500,000-pool vectorized check returned
`0.500392` for the ratio of mean gains and `0.334524` for mean pool ratios.

Reproduce the existing implementation, with the repository environment:

```sh
PYTHONPATH=src .work/.venv-cu126/bin/python -c \
  'from gain_law_simulation import simulate; print(simulate("gaussian", .25, 2, 1, 50000, 20260913)["latent_ratio"])'
```

The cross-half implementation also uses a sample standard deviation where
the exact identity uses population standard deviation. Real-artifact gain
averages both directions; the synthetic path evaluates one direction.
The manuscript's concurrent revision identifies several of these distinctions,
but that clarification does not change the estimator or validate an exact
finite-pool calibration claim.

This does not refute the Gaussian proposition or establish a discrepancy of
the same size at the published `n=400`. The simulation and its generated
paper assets were deliberately not silently replaced in this audit.
Resolve by reporting the actual statistic as a descriptive finite-pool
simulation, or by separately generating and validating the theorem's
ratio-of-expectations statistic with synchronized manuscript assets.

### P1: Reliability is not a measured continuation-benefit guarantee

The Gaussian result bounds latent score gain. The retained score's
relationship to actual optimizer updates and later reward is an additional
assumption. Neither the threshold nor the code tests establishes it.
The decision-proof note separates utility validity, utility spread,
reliability, and cost, but does not supply measured values for that bridge.

The E5 gate measures current-policy difficulty during ten training updates
and may then retain a subset selected from the old cache. At d400 seed 2,
retention ends 2.9583 percentage points below unchanged difficulty, with
paired prompt-bootstrap interval [1.1667, 4.7083]. The 10+90 and 100-update
paths differ, so this is an adverse complete-procedure outcome, not an
isolated fallback effect or a counterexample to the discarded experiment.

The accepted export contains no cost-accounting block. Do not infer zero
cost, net savings, seed-level significance, or absent running experiments.

`v3/reviews/2026-09-13-current-manuscript-code-review_ko.md`.
