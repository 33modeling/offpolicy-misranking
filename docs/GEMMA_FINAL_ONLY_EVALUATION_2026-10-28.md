# Gemma 중간 평가 생략과 최종 결과 우선

2026-10-28 사용자 요청에 따라 운영 실행기의 기본값을 **최종 평가만 실행**하도록 바꿨다. 기존 코드는 25업데이트마다 고정 held-out 질문에 질문당 8개 응답을 생성하는 별도 평가를 동기 실행했다. 이 경로의 호출은 코드 검사로 확인했으며, 실제 원격 Gemma 정체의 유일 원인이라고 단정하지 않는다.

25업데이트별 가중치 아카이브와 옵티마이저가 포함된 재개 체크포인트, 매 업데이트의 학습 보상과 원시 rollout을 보존한다. 같은 경계의 유효한 아카이브는 다시 덮어쓰지 않는다. 생략한 held-out 평가는 `held_out_reward: null`인 별도 영수증에 남기고 결과 내보내기에서도 `not_measured`로 구별한다. 이미 측정한 평가와 기존 프로토콜은 유지한다. 학습 보상을 held-out 보상으로 대신하지 않는다.

고정 학습기와 최종 평가기는 바꾸지 않았다. 원래 마지막 업데이트의 평가와 최종 endpoint 저장, 완료 판정은 그대로 실행한다. 모델, 데이터, seed, 학습 횟수와 샘플링 프로토콜을 바꾸거나 결과 root를 초기화하지 않는다. Gemma PT/text/IT, Qwen, Llama의 공통 운영 recorder에 적용된다.

`SRGC_INTERMEDIATE_EVAL`의 기본값과 `0`은 중간 평가를 생략한다. `1`을 명시하면 기존의 중간 평가를 사용할 수 있다. 기존 root를 사용하는 공개 명령의 예는 다음과 같다.

```sh
git pull --ff-only
SRGC_INTERMEDIATE_EVAL=0 bash scripts/run_srgc_gemma4.sh resume --root "$EXISTING_ROOT"
```

`EXISTING_ROOT`에는 실제 실행 중이던 결과 경로를 사용한다. 이 명령을 로컬에서 임의 경로로 실행하지 않았으며, `reset`을 하지 않는다. 새로 시작하거나 재개하는 worker부터 적용되고 이미 실행 중인 Python 프로세스에 코드를 주입하지 않는다. 기존 worker가 실행 중인 실제 노드의 현재 상태는 별도로 확인해야 한다.

CPU 검사에서는 실제 작은 AdamW 옵티마이저로 25→26 재개, 모든 비교 방법의 275업데이트·최종 평가·endpoint 복구, 평가 생략 전후 같은 옵티마이저 궤적, 기존 측정 보존을 검사한다. 이는 원격 Gemma 12B 학습이나 정답률·GPU 시간 측정이 아니다. 실제 GPU 노드와 결과 root가 연결되지 않아 원격 25→26 진행, 최종 Gemma 보상과 실제 속도 개선은 미검증이다. 실패와 미완료 검사 기록도 함께 보존한다.
