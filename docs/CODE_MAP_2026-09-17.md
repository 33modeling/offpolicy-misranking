# 코드 지도 — 무엇이 무엇을 하는가

작성 2026-09-17. 대상은 실행 레포 `offpolicy-misranking`(코드) 한 곳이다.
원고는 `offpolicy-misranking-paper`, 감사 기록은 `offpolicy-misranking-final-audit`에 있고
이 문서는 그 둘을 다루지 않는다.

기존 문서를 대체하지 않는다. 설계 결정의 정본은 각 `docs/*.md`이고, 이 문서는
**코드를 처음 여는 사람이 전체 배치를 파악하는 지도**다. 수치는 전부 코드와
`configs/olmo3_rlzero.json`에서 직접 읽었다.

규모: `src` 117개 모듈·약 3.4만 줄, `scripts` 78개, `tests` 136개 파일·테스트 함수 1,093개.

---

## 1. 실험 한 점(point)이 무엇인가

이 실험의 최소 단위는 **(데이터셋, 시드, drift) 한 조합**이고 이를 point라 부른다.
`configs/olmo3_rlzero.json`의 본실험 매트릭스는 다음과 같다.

| 축 | 값 | 개수 |
|---|---|---|
| 모델 | OLMo-3-1025-7B base (revision 고정) | 1 |
| 데이터셋 | MATH-500, MBPP | 2 |
| 시드 | 0, 1, 2, 3, 4 | 5 |
| drift | 0, 25, 100, 400 | 4 |

곱하면 40 point다. drift는 **behavior 정책 β를 만들기 위해 돌린 GRPO 학습 스텝 수**다.
d0은 학습을 전혀 하지 않은 base 정책이 곧 β이고, d400은 400스텝 학습한 정책이 β다.
point 하나는 `scripts/run_point.sh`가 8단계로 처리한다.

```
1 prep              프롬프트 분할 고정 (train n=400/512, val n=100)
2 rollout-behavior  β로 학습 프롬프트당 K=8 응답 생성
3 grpo              β를 만들기 위한 GRPO 학습 (d0이면 건너뜀)
4 rollout-fresh     현재 정책 π로 학습 프롬프트당 K=32 + val K=8 생성  ← 가장 긴 단계
5 oracle+val grads  fresh 롤아웃에서 참값 gradient 계산
6 score             β 롤아웃에 4개 추정량 적용 → 프롬프트별 점수
7 merge + report    shard 병합, 보고서 생성
8 DONE
```

4·6단계는 GPU 수만큼 shard로 쪼개 병렬 실행하고(`--shard i:n`), 모든 shard가
끝나야 다음으로 넘어간다. 각 단계는 산출물이 이미 검증된 상태면 건너뛴다(재개 지원).

## 2. GRPO 학습 — 응답을 몇 개 생성하나

`src/train_policy_grpo.py`(1,300줄). 4-GPU DDP로 돈다.

**한 스텝에서 생성하는 응답 수는 32개다.** 근거는 이렇다.

- 랭크(=GPU)마다 프롬프트를 **하나** 잡는다.
  `prompt_index = (seed * 37 + step * world_size + rank) % len(prompts)`
- 그 프롬프트 하나에 대해 `_sample_group()`이 `group_size`만큼 응답을 만든다.
  입력을 `expand(group_size, -1)`로 복제해 한 번에 생성한다.
- `world_size = 4`, `group_size = 8` → 스텝당 프롬프트 4개, 응답 4 × 8 = **32개**.
- 코드도 이 값을 매니페스트에 `samples_per_step = world_size * group_size`로 기록한다.

따라서 d400 point 하나는 400스텝 × 32 = 12,800개 응답을 생성하며 학습한다.

생성 설정과 학습 하이퍼파라미터:

| 항목 | 값 | 비고 |
|---|---|---|
| `group_size` | 8 | 한 프롬프트당 응답 수 = advantage 그룹 크기 |
| `world_size` | 4 | DDP 랭크 수, 실제 world size와 불일치하면 abort |
| `max_new_tokens` | 2048 | |
| temperature | 1.0 | `_sample_group`이 하드코딩 |
| `top_p` | 1.0 | 전 단계 통일 (P0 감사 결과) |
| `clip_epsilon` | 0.2 | PPO식 clipped surrogate |
| `learning_rate` | 1e-5 | |
| `epochs_per_batch` | 1 | 한 배치를 한 번만 재사용 |
| `max_grad_norm` | 1.0 | |
| `reference_kl_beta` | 0.0 | **KL 페널티 없음** |
| `advantage_epsilon` | 1e-4 | 표준화 분모 하한 |
| LoRA | rank 16 / alpha 32 / `q_proj`,`v_proj` | base 가중치는 동결 |
| `checkpoint_every` | 5 | 스텝 |

**목적함수는 세 가지**를 지원한다(`RLVR_METHODS = ("grpo", "dr_grpo", "rloo")`).
셋의 차이는 advantage를 어떻게 만드느냐 하나로 갈린다.

| 목적함수 | advantage | 구현 |
|---|---|---|
| `grpo` | 그룹 내 표준화 (평균 빼고 표준편차로 나눔) | `standardized_group_advantages` |
| `dr_grpo` | 그룹 평균만 뺌 (표준편차 나눗셈 없음) + 토큰 정규화 `max_new_tokens` | `centered_group_advantages` |
| `rloo` | leave-one-out | `rloo_group_advantages`, old logp 불필요 |

`grpo`와 `dr_grpo`는 현재 정책과 생성 시점 정책의 log-prob 비를 clipped surrogate로 쓰고,
`rloo`는 비 없이 `-advantage × Σ logp`를 바로 쓴다. 매 스텝 advantage가 전부 0이면
(그룹 전원 정답이거나 전원 오답) 그 랭크는 비활성으로 기록되고, 활성인데 gradient norm이
0이거나 비정상이면 **에러로 멈춘다** — 조용한 무학습을 막는 장치다.

## 3. 핵심 질문과 2×2 추정량

`src/grads.py`. 이 레포가 존재하는 이유가 여기 있다.

묻는 것은 이렇다. **낡은(stale) 롤아웃으로 매긴 프롬프트 순위가, 현재 정책으로
새로 뽑아 매긴 순위를 얼마나 보존하는가.** 보존하지 못하면 stale 데이터로 고른
프롬프트가 엉뚱한 것이 된다.

β 롤아웃에 중요도 가중을 어디까지 거느냐로 추정량 4개가 갈린다.

| 추정량 | 식(unclipped) | 교정 범위 |
|---|---|---|
| `g00` | `Σ_t E_β[ r_t R z_t ]` | 토큰 비만 (CROPI 방식) |
| `g10` | `Σ_t E_β[ P_t r_t R z_t ]` | prefix만 교정 |
| `g01` | `Σ_t E_β[ r_t S_t R z_t ]` | suffix만 교정 |
| `g11` | `Σ_t E_β[ P_t r_t S_t R z_t ]` | 전 궤적 (= 완전한 IS) |

`R` 자리는 전부 leave-one-out 비정규화 advantage `A_j = R_j − mean_{l≠j} R_l`를 쓴다.
실험값은 토큰별 곱을 `[1/clip_cap, clip_cap]`(= `[0.1, 10]`)으로 자른 clipped variant다.
클리핑 전에는 baseline이 소거되지만 클리핑 후에는 그 항등식이 깨지므로,
그 차이는 clipping bias로 따로 해석한다.

**참값(oracle)** 은 현재 정책 π로 새로 뽑은 fresh 롤아웃의 LOO 그룹 gradient다.
`fresh_k = 32`개를 `micro_group = 4`로 쪼개 여러 독립 추정을 만들고, 이걸로
점수의 신뢰도(split-half)까지 같이 잰다.

gradient는 그대로 쓰기엔 너무 커서 `proj_dim = 4096` 차원으로 무작위 투영하고
(`ProjectionSpec`, `project_grads`), 마지막 `grad_layers = 4`개 층만 쓴다.
프롬프트 점수는 투영된 gradient의 코사인이다.

선택은 `topk_frac = 0.1` — 상위 10%를 고른다(`select_rules.py`가 크기 규칙 단일화).

## 4. 데이터와 보상

`src/data.py`(883줄). 로컬 우선으로 읽고, 없으면 미러를 본다.
`load_prompts(dataset, n_train, n_val, seed)` 하나가 입구다.

보상은 `reward(text, gold)` 한 함수가 gold 문자열의 머리글자로 분기한다.

| 조건 | 채점 방식 |
|---|---|
| `assert`로 시작 | MBPP — 샌드박스에서 실제 실행 |
| `APPS:` | stdin/stdout 실행 채점 |
| `KK:` | knights & knaves — 전원 신원 매치 |
| `ARC:` / `MMLU:` | 보기 라벨 정확 일치 |
| 그 외 | 수학 — 답 추출 후 정규화 비교, 실패 시 수치 동등(1e-6), 그래도 실패면 `math_verify` |

재채점**할 수 있게 해 뒀다. 롤아웃 자체는 다시 생성하지 않는다.

## 5. 판정과 신뢰도

수치가 나왔다고 바로 결론을 내지 않는다. 판정 경로가 따로 있다.

- `judge.py` — report·hybrid·downstream 산출물만 읽어 통과/사망을 기계적으로 출력.
  사람이 눈으로 고르는 여지를 없앤다. 규칙은 `gate_rules.py`에 모아 뒀다.
- `kcurve_floor.py` / `kcurve_all.py` — oracle 롤아웃 수 K를 바꿔 가며 floor가
  어떻게 움직이는지 재계산한다. GPU를 쓰지 않고 저장된 산출물만 쓴다.
  **관측 floor가 K에서 하강하면 신호가 아니라 포화-공유 인공물**이라는 판별이
  여기서 나온다.
- `measurement_ceiling.py` — 주어진 설계에서 측정 가능한 상한. 이 위로는
  어떤 방법을 써도 우열을 가릴 수 없다.
- `stats_extra.py` — 초기하 p값·프롬프트 부트스트랩·부호검정.
- `first_interval.py` — 계층 부트스트랩 신뢰구간.

`readout_summary.py`가 이 결과들을 사람이 읽는 `READOUT.md`로 묶는다.

## 9. 코드를 건드릴 때의 규약

이 레포는 여러 노드·여러 세션이 동시에 돌기 때문에 규약이 몇 가지 있다.

1. **기존 파이프라인 파일은 수정하지 않고 새 파일을 만든다.** E1~E6, 게이트 계열,
   선택 전환이 전부 이 방식으로 들어왔다. 돌고 있는 실험의 코드 해시가 바뀌면
   그 실험이 통째로 무효가 된다.
2. **`run_point.sh`는 `src`/`scripts`가 더티하면 abort한다.** 새 파일 추가도 더티다.
3. **`run_matrix.sh`는 가족의 첫 실행 커밋을 생성 커밋으로 고정한다.** 코드를 바꾸려면
   work 디렉터리를 초기화해야 한다.
4. **로그는 저장소에 남기지 않는다.** 전부 `$OM_WORK/console-logs/`로 간다.
5. `run_config.json`이 config를 잠근다. digest가 안 맞으면 abort하고,
   `verify_code_snapshot`이 스테이지마다 실행 중 pull을 막는다.
