# Gemma 초기 캐시 우선 실행 — 2026-10-21

공개 `sh scripts/run_srgc_gemma4.sh all` 명령은 MATH·MBPP의 모든 seed 초기 캐시를
먼저 만든 뒤 MATH 학습을 시작한다. MATH의 캐시 lease가 다른 노드에 있으면 빈 노드는
MBPP 캐시를 맡는다. 실패한 캐시의 재시도 대기 중에도 다른 준비된 캐시를 진행한다.

기존 task·실행·GPU lease를 그대로 사용하므로 같은 캐시를 두 노드가 동시에 맡지 않는다.
다른 노드의 캐시가 완료 직전이어도 lease가 남아 있으면 학습으로 넘어가지 않는다.
캐시 단계에서는 prefix와 학습 arm을 배정하지 않는다. MBPP 학습은 MATH 다음이다.
중지 요청은 캐시에도 적용하고, 두 단계 사이에 새 중지 요청을 다시 지우지 않는다.

입력·sampling·seed·보상·checkpoint·시간 집계와 실험 해시는 유지한다. 완료된 캐시와
개별 후보의 원시 응답은 재사용하며 초기화하지 않는다. 새 명령이나 별도 실행 파일은 없다.
실행 중인 Python 프로세스에 코드를 주입하거나 학습을 강제로 종료하지 않는다.
업데이트 후 새로 실행되는 공개 worker부터 이 배정 순서를 사용한다.

검사는 [캐시 우선 테스트](../srgc_research/tests/test_gemma_cache_first.py), 기존 공개 진입점·중지
검사·배정·다중 노드 재개 검사와 함께 **281개 검사 통과**를 확인했다.
CPU 제어 검사이며 원격 H100 캐시를 실제 시작한 기록은 아니다.
