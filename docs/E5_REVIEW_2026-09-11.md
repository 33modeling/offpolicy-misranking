# Reduced E5 Review And Repairs

Reviewed baseline: `e6bf22e`; reduced E5 was introduced by `a1004ee`.

## Repairs

- OLMo and Qwen status entrypoints only report the installed revision. Removed
  automatic fetch/merge and the model-specific liveness condition, which did
  not protect an E5 launcher reading the same checkout.
- Qwen status no longer runs a failing `pgrep | wc` under `set -e -o pipefail`
  before reaching the renderer. An idle local node can inspect remote work.
- The E5 launcher checks for a verified recovery checkpoint before skipping an
  invalid final policy. The new read-only probe reuses the trainer's checkpoint
  contract and hash validation, checks source/code/model/subset bindings, and
  authorizes only the existing trainer's repair path. Unrecoverable arms remain
  preserved, and the launcher continues to other arms.

The hashed `evidence_downstream.py`, trainer, evaluator, selector and reward
implementations are not edited. No contract migration, output deletion, new
GPU job or restart of the running experiment is part of this repair.

## Experimental Scope

The running default is MATH d400, seeds 0/1/2, random/fresh-R/g11, 100 additional
updates, 300 disjoint MATH-train questions with 8 responses each. It tests fixed
subset training value. The earlier proposed comparison of alignment-selected
versus overlap-selected correction methods is separate and is not implemented
by the three-arm default. Paper and bilingual reader must distinguish these
designs without inventing downstream observations.

## Verification

CPU regression tests cover both real status entrypoint prologues, no local
Qwen process, missing Git metadata, E5 activity, read-only repair probing,
complete/intermediate checkpoints, incompatible seeds/parents/targets,
corruption, source/subset/model/code changes, unchanged prepared contracts,
and launcher continuation after a repairable or unrecoverable arm.

Full CPU suite: 583 passed in 339.42 seconds. The four warnings are Python's
multi-threaded `fork()` deprecation warning in existing rescore process-pool
tests; no test failed. The focused recovery/status/E5 suite passed all 56 tests.

No cluster GPU execution was performed. Install after the shared launcher
exits and rerun the same E5 command; healthy work need not be stopped.

## Integration With The Concurrent Progress Update

After `ab21fee` was pushed, `8a5ad8f` added detailed progress. Its new diagnostics
changed `evidence_downstream.py`, whose full-file hash is frozen in existing
contracts, and its 30-second completion poll failed both launcher regression
cases (15-second timeout even with instant mock evaluation).

The detailed shard counts, log tails and training checkpoints are retained in
`src/downstream_status.py`, reached by the same `bash scripts/run_e5.sh status`
command. The scientific file is byte-identical to `ab21fee` again. Console
progress still appears every five minutes, but completion is polled once per
second instead of delaying the next arm by up to 30 seconds. Log tails read a
bounded suffix instead of the entire file. Empty shard files print a single zero.

Existing contracts from `a1004ee` through `ab21fee` retain their original hash.
Do not rewrite `experiment.json` to bypass a code mismatch. An experiment newly
prepared specifically under intermediate `8a5ad8f` has a different code hash;
keep that pinned revision for those outputs instead of silently migrating them.

Final integration verification: all 63 recovery, detailed-status, E5 contract
and OLMo/Qwen status tests passed in 8.27 seconds, including the two previously
timing-out launcher cases. The new status command also runs without site
packages or CUDA. The scientific file hash is guarded by a regression test;
all nine scientific files match the pre-progress revision. Bash syntax and
`git diff --check` pass. The earlier 583-test full-suite result applies to
`ab21fee`; this follow-up was verified with the focused 63-test suite.
