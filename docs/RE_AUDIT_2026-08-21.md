# 2026-08-21 코드·수식·원고 재감사

## 판정

- 2x2 population identity, 두 sign-reversal witness, indistinguishable-pool
  lower bound, binary group normalization, Gaussian measurement ceiling, exact
  top-k lower bound를 다시 검산했다. 알려진 대수 오류는 없다.
- `scripts/verify_theory.py`는 sign reversal, KL의 `8 epsilon^2` 전개,
  indistinguishable pools, LOO unbiasedness, group normalization(K=2..1024),
  angular radius, 50k random search를 통과했다.
- CPU 회귀 테스트는 24개가 통과했다. Python compile과 모든 shell `bash -n`도
  통과했다.
- 기존 v2/v3 수치는 모두 generation-contract 수정 전 산출물이다. 논문의
  confirmatory evidence로 사용할 수 없고 corrected v4 수확으로 교체해야 한다.

## 이번에 수정한 코드 결함

1. `prompt_gradient`가 response log-probability와 token weight 길이가 다르면
   짧은 쪽으로 조용히 잘랐다. 이제 sequence 수, response boundary, token 길이를
   exact-match로 검사하고 불일치 시 중단한다.
2. drift SFT의 1280-token 절단점 뒤에서 response가 시작하면 prompt token 하나를
   정답 label로 남길 수 있었다. response가 절단으로 사라지는 행은 중단하고,
   prompt 전체를 정확히 `-100` 처리한다.
3. 한 토큰 response가 EOS뿐인 hybrid source에서 EOS를 prefix로 보존한 뒤
   continuation을 시도했다. 모든 source의 마지막 token을 terminal candidate로
   제외하고, 한 토큰 response는 prompt부터 다시 이어 생성한다.
4. hybrid JSONL의 네 cell이 같은 prompt 집합과 exact `K_CELL`을 실제로 갖는지
   검사하지 않았다. `bb/bp/pb/pp` 전수 coverage, cell label, exact-K를 scoring
   전에 fail-closed로 검증한다.
5. generation manifest가 설정과 범위만 기록하고 JSONL bytes를 묶지 않았다.
   신규 생성물은 artifact SHA-256을 generation 시점에 기록한다. validator는
   manifest/hash, exact rollout index, shard와 merged row의 내용 일치를 확인한다.
   구 manifest는 진행 중 v4를 폐기하지 않도록 validation-time hash를 protocol에
   봉인하고 `generation_hash_missing`에 명시한다.
6. adapter보다 오래된 rollout JSONL을 격리할 때 sidecar manifest가 남았다.
   fresh/hybrid manifest와 stale shard sidecar를 데이터 파일과 함께 격리한다.
7. hybrid protocol을 v2로 올리고 rollout/input/output hash snapshot을 기록한다.
   report도 score, oracle, split-half, micro-group, validation, protocol 입력 hash를
   기록하며 이후 CPU 판정은 snapshot drift를 거부한다.
8. corrected postprocess의 `Namespace`에 `val_k`가 없어 `stage_report`에서
   `AttributeError`가 날 수 있었다. run config의 `val_k`를 전달한다.
9. script형 테스트의 import-time `sys.exit` 때문에 표준 `pytest` collection이
   중단됐다. 직접 실행 동작을 보존하면서 pytest entry point를 추가했고,
   `requirements-dev.txt`에 pytest/ruff를 명시했다.
10. 정답 rollout이 0개면 drift SFT가 모든 오답 rollout을 학습하던 smoke fallback이
    본실행에도 적용됐다. 잘못된 policy drift를 만들지 않도록 positive target이 없는
    pool은 즉시 중단한다.
11. rollout 생성 시작 시 최종 manifest를 먼저 덮어써, 중단되면 이전 JSONL과 새
    미완성 sidecar가 섞일 수 있었다. 진행 상태는 `.tmp`에만 쓰고 JSONL hash 계산
    이후 최종 manifest를 원자적으로 게시한다.
12. legacy `val-deepen`은 기존 validation JSONL에 `rollout_idx=0..K-1`을 다시
    append하면서 immutable `run_config.val_k`도 갱신하지 않았다. 기존 run의 계약과
    후속 protocol을 오염시키므로 in-place 심화를 금지하고 큰 `VAL_K`의 새 run을
    요구한다.

## 원고와 결과 해석 교정

- v2에서 보였던 McNemar `p=0.014`와 disagreement Fisher
  `p=0.0069..0.034`는 v3 MATH-500에서 재현되지 않았다(McNemar 최소
  `p=0.23/0.52`, Fisher `p=0.37/0.38`). estimator reversal `41..51%`도
  oracle self-disagreement `44..48%`와 구별되지 않는다.
- v2와 v3가 모두 pre-contract이고 task/seed 구성이 다르므로 차이를 계약 수정
  효과로 해석할 수도 없다. 해당 유의성 주장은 철회하고 corrected rerun의
  사전 고정 검정으로만 유지한다.
- historical policy replay에서는 stale `0.275`, pass rate `0.265`, full-fresh
  `0.225`, floor-gated `0.212`였다. 처방 우위의 근거가 아니며 FIRST는 audit과
  corrected test hypothesis로만 유지한다.
- 새로 확인한 가까운 선행연구는 Zuk et al. (2007)의 noisy top-k overlap과
  M2PO (Zheng et al., 2025)다. 전자는 stale-policy correction/conditional ceiling을,
  후자는 prompt ranking reliability를 다루지 않으므로 직접 선취는 아니지만 원고에
  차이를 명시해 인용한다.

## 남은 제출 blocker

- corrected v4 seed matrix의 TABLES/KCURVE/FRONTIER/READOUT/REVERSAL/STATS 수확
- 27B에서 live prompt와 nonzero boundary margin을 확보한 능력-난이도 정합 검정
- drift-training prompt와 selection pool을 분리한 ablation
- official/symbolic math verifier 감사와 projection/full-gradient calibration
- prompt-cluster bootstrap, paired cell tests, downstream equal-cost repeated seeds
- ICLR style, page budget, anonymity, reproducibility/AI-use/ethics appendix

현재 실행 중인 old-commit GPU run을 이 변경 때문에 종료할 필요는 없다. 다만 그
run의 수치는 실행 commit과 protocol marker를 그대로 보존해야 하며, 최신 코드로
후처리할 때 validation-time hash가 추가된다. 신규 run은 generation-time hash와
hybrid v2 계약을 사용한다.
