## §1 치명 — π가 채점 대상 β 표본으로 학습됨 (수정)

| 항목 | 내용 |
|---|---|
| 위치 | `experiment.py` drift 단계 → `rollouts_behavior_train.jsonl`로 LoRA RFT; `stage_score`가 **같은 파일**에 π/β 비율을 매김. `rollout.train_drift_lora`는 정답 행을 파일(prompt_idx) 순서로 셔플 없이 `steps×batch`개만 소비 |
| 결과 | π가 채점 표본의 함수 → `E_β[w·f]=E_π[f]` 항등식 전제(π ⟂ 표본) 붕괴. 앞쪽 절반 프롬프트의 정답 rollout만 외운 상태라 r_t 편향이 프롬프트 인덱스에 따라 갈림. `token_kl_beta_pi<0`(RESULTS_0820의 −0.57)은 이 설계에서 필연이며 생성 계약 수정과 무관하게 남음 |
| 수정 | 새 stage `rollout-drift`(채점용과 같은 프롬프트·K, 다른 난수 스트림) → `rollouts_drift_train.jsonl`; drift는 이 파일만 받고 생성 계약을 검증한 뒤 학습, `drift_source.json` 기록. `train_drift_lora`는 run seed로 정답 행 셔플. `score_protocol.json`에 `drift_source` 필드(`disjoint` / 구 run은 `shared-legacy`) |
| 비용 | run당 β rollout 한 벌 추가(N샤딩, 7B 4장 기준 ~40분) |
| 진단 | 기존 run에서 drift에 쓰인 앞 400행과 나머지로 나눠 `kl_sum`을 따로 집계 — 나머지에서도 음수면 likelihood/샘플링 불일치가 추가로 남아 있음 |

## §2 실행 경로 (수정)

- **stale shard manifest 미격리** — `run_14b.sh` 정합성 검사가 옛 샤드 `.jsonl`만 치우고
  `.shard*.manifest.json`은 남겨, `artifact_contract.source_manifests`가 범위 겹침으로 raise →
  GPU 수가 바뀐 재시작이 매 재시도마다 score/merge에서 사망. → 현재 분할·범위와 안 맞는
  manifest도 격리(`rollouts_drift_train` 포함).
- **`val-deepen`이 run 오염** — append로 `rollouts_fresh_val` 행 수가 `run_config.val_k`와
  어긋나 protocol 마커 재생성 불가 + 고아 manifest. → stage·`deepen_val.sh` 모두 거부(fail-closed).
  심화는 `VAL_K`를 키운 새 OUT_ROOT로.
- **hybrid `--micro-batch` 무시** — `score_cells`가 기본 2로 고정. → 인자 관통.
- **`pkill -f "--run $OUT_ROOT"` 접두 매치** — `v2-s1`이 `v2-s1-dapo-math` 프로세스까지 죽임
  (순차 실행에선 무해, 병렬에선 형제 run 사망). → `( |$)` 경계 추가, go_v2는 run 단위 정리만.

## §3 판정 일관성 (수정)

- **동률 jitter 시드** — `stage_report`는 `--seed`, judge/readout/stats/make_tables/reversal은 0
  고정. 점수 0 동률이 수백 개인 풀에서 s1/s2의 report.json과 표·판정 수치가 어긋났다.
  → `gate_rules.run_seed(run)`(=`run_config.seed`)로 전 도구 통일.
- **uniform baseline val 깊이** — `certagrad.uniform_baseline`이 val 그룹 수를 후보 깊이로
  잘라(4/50) 기준선만 잡음이 컸음. → 기본 val_pool 전체, `stage_report`가 명시 전달.

## §4 확인 권장 (일부 수정)

- **`extract_answer` 첫 `####`** → 마지막 `####`(한 줄 다중 마커도 분리 매치). 보상 의미가
  바뀌므로 구 run 수치와 직접 비교 금지.
- **bf16 logprob** — `grads.sequence_logprobs`/`prompt_gradient`가 bf16 logits를 사후 `.float()`.
  토큰당 ~0.05nat 반올림이 300토큰 궤적 가중치에 누적될 수 있음. `OM_DTYPE=float32`로
  부분집합 재계산해 log-weight 차이를 한 번 재볼 것(run_config에 `dtype` 기록).
- **DAPO `MAX_NEW_TOKENS=512`** — "oracle 무신호 91~95%"는 절단 보상 0일 가능성. 판정 전에
  토큰 예산부터(코드 수정 없음, 실행 설정).

## §5 속도 — go_v2 병렬화 (추가)

`go_v2.sh`는 seed×dataset을 완전 순차로 돌려 6 run에 2~3일이 걸렸다(전 구간 `OM_ATTN=eager`).
`PAR=N`이면 GPU를 N 그룹으로 나눠 job을 동시에 N개 돈다(run_14b의 `OM_GPUS` 분할). 기본
`PAR=1`은 종전 동작. 결과 수집·요약은 파일(`console-logs/v2-results.<pid>/`)로 취합.

```bash
PAR=2 bash scripts/go_v2.sh                 # 8장이면 4장씩 두 run 동시
PAR=2 SEEDS="3 4" RUN_BASE=... bash scripts/go_v2.sh   # 별도 인스턴스도 안전(run 단위 정리)
```
