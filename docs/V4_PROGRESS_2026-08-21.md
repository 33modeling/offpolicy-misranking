## 로그에 보이는 정답 수치

진행 로그가 보존한 마지막 세 prompt만 합산하면 다음과 같다. 전체 run 평균이
아니므로 효과크기나 seed 비교에는 쓰지 않지만, reward-variance 방향은 읽을 수 있다.

| run/log | 마지막 3 prompt 정답 | 합계 | reward가 섞인 prompt |
|---|---:|---:|---:|
| s0 `fresh-shard1` | 32/32, 32/32, 32/32 | 96/96 (100%) | 0/3 |
| s3 `beta-shard3` | 8/8, 4/8, 7/8 | 19/24 (79.2%) | 2/3 |
| s4 MATH-500 `fresh-shard0` | 0/32, 0/32, 3/32 | 3/96 (3.1%) | 1/3 |
| s4 GSM8K `main` (stage 이름 불명) | 32/32, 31/32, 32/32 | 95/96 (99.0%) | 1/3 |

이 숫자가 주는 직접 판정은 다음과 같다.

1. 27B GSM8K fresh는 사실상 all-correct 포화다. s0 tail의 세 prompt 모두
   leave-one-out advantage가 정확히 0이고, s4 tail도 두 prompt가 0이다.
   이 pool에서는 네 cell의 순위 차이보다 oracle 자체의 무신호가 먼저 나온다.
2. MATH-500 tail은 반대로 all-wrong 쪽에 가깝다. `0/32` 역시 advantage가
   정확히 0이므로, 단순히 어려운 dataset으로 옮기는 것만으로 신호가 생기지 않는다.
3. 현재 보이는 창 중 reward variance가 가장 살아 있는 것은 s3 behavior의
   `4/8`, `7/8` 두 prompt다. 다만 서로 다른 seed와 behavior/fresh stage를
   직접 비교해 drift 효과라고 해석할 수는 없다.
4. 따라서 현재 full-dataset run은 논문의 capability-saturation/measurement-first
   주장을 확인하는 데 유용하지만, one-sided misranking의 27B 실증을 주력으로
   만들기에는 난이도 calibration이 부족하다.

현재 run은 중단하지 않고 완주해 양 극단의 무신호 비율을 정량화한다. 다음 확장 전에는
각 source별 `0/K`, `K/K`, `0<correct<K` prompt 비율을 먼저 수확한다. GSM8K와
MATH-500 모두 중간 reward variance가 부족하면, 분석 seed와 분리된 prescreen으로
`0<correct<K`가 재현되는 model-calibrated pool을 고정한 뒤 그 pool에서 다중 seed를
실행한다. 이것이 27B에서 one-sided 가설을 검증하는 결정적 후속 실험이다.
